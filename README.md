# Servidor Android — prova de conceito

Código original sob licença MIT; dependências mantêm suas licenças e avisos em `THIRD_PARTY_NOTICES.md` e `licenses/`. A preparação do repositório privado está documentada em `docs/private-repository.md`.

Projeto independente para gerenciamento de servidores Minecraft Java no Android. O APK de referência não é usado ou modificado.

Estado: APK de prova de conceito com launcher C ARM64, OpenJDK 25 empacotado e interface escura em português. O teste real da JVM no Galaxy S23 FE falhou com `Failed setting boot class path`; nenhum servidor Minecraft foi iniciado. A compatibilidade real permanece pendente.

`ProcessConsole` implementa o gerenciamento de um processo filho: estados, leitura de logs, escrita de comandos, envio de `stop` e encerramento forçado após prazo. `ServerSession` conserva o processo e as últimas 400 linhas durante recriações da Activity. A interface permite criar perfis locais, importar JAR e arquivos para a pasta privada de cada perfil, editar configurações e aceitar a EULA explicitamente. O JAR do servidor deve ser obtido de fonte autorizada; não está incluído.

## Interface e limites atuais

A interface própria usa tema escuro, cartões grafite, verde esmeralda e ícones vetoriais originais. A navegação separa Início, Servidores, Criar, Arquivos e Ajustes. O assistente tem oito etapas: informações, software, versão, memória, mundo, jogadores, rede e revisão. O painel reúne console, arquivos, mundos, mods, plugins, backups, ajustes e diagnóstico; backups aparecem como indisponíveis. As categorias Vanilla, Paper, Purpur, Fabric, Fabric Otimizado, Forge e NeoForge organizam perfis; **não fazem download nem verificam a compatibilidade do JAR**. A consulta opcional ao catálogo oficial da Mojang mostra a última versão estável e versões anteriores, além do Java exigido por uma versão selecionada; não valida o software escolhido. GeyserMC e Floodgate aparecem como indisponíveis. O gerenciamento de arquivos é limitado à navegação e importação para o armazenamento privado do app; não há edição ou exclusão. A RAM escolhida é passada ao launcher como `-Xmx`; dificuldade, modo de jogo, autenticação, porta TCP e acesso LAN são gravados em `server.properties` antes de iniciar. Tipo de mundo e porta UDP ficam salvos no perfil até haver verificação de compatibilidade e integração. Um servidor funcional ainda depende da correção e do teste real da JVM. Não há serviço em primeiro plano para manter o processo ativo em segundo plano.

O APK Anvil-MC foi usado apenas para observar categorias de navegação e organização de fluxos, via análise estática do APK. Nenhum código, layout, imagem ou ícone do aplicativo de referência foi incorporado.

Build verificado no Windows 11: JDK 21, Gradle Wrapper 8.11.1, Android Gradle Plugin 8.9.1, Kotlin 2.1.20, Android SDK Platform 36 e Build Tools 36.0.0. O comando `gradlew.bat --no-daemon --console=plain --offline assembleDebug` gera o APK do pacote `org.openmc.server`. Para preservar C:, a compilação atual usa `OPENMC_BUILD_DIR=W:\Backup-Pedro\minecraft-open-server-tools\project-build\app`; o APK atualizado fica em `W:\Backup-Pedro\minecraft-open-server-tools\project-build\app\outputs\apk\debug\app-debug.apk`. Sem essa variável, a saída permanece em `app/build/outputs/apk/debug/app-debug.apk`. O JDK 21 instalado no Windows serve apenas para compilar; ele não é uma JVM Android. Nenhum servidor foi executado.

Nesta máquina, `.tools` é um vínculo para `W:\Backup-Pedro\minecraft-open-server-tools`. O HD externo deve estar conectado como `W:` para compilar. Configure apenas nesta sessão do PowerShell `JAVA_HOME` para o JDK 21, `ANDROID_HOME` e `ANDROID_SDK_ROOT` para `.tools\sdk`, `ANDROID_USER_HOME` para `.tools\android-user`, `GRADLE_USER_HOME` para `.tools\gradle-cache` e `ANDROID_NDK_HOME` para `.tools\sdk\ndk\30.0.16248370`. ## Runtime e integração nativa

1. O [Minecraft Java 26.1 exige Java 25](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1); o [Paper 26.1+ também](https://docs.papermc.io/paper/getting-started/). Por isso o APK usa o [OpenJDK 25 ARM64 do Amethyst](https://github.com/AngelAuraMC/angelauramc-openjdk-build/releases/tag/download_jre25), build ligado ao [workflow 7a0266e](https://github.com/AngelAuraMC/angelauramc-openjdk-build/actions/runs/31798797699). SHA-256 do arquivo original: `d3eb7afe2240c26728a1bb440502c5f18ac3883e932d202dd7f0c9bcbbce4c37`. O arquivo `release` informa OpenJDK 25.0.5. As bibliotecas são ELF 64 bits AArch64; as licenças GPLv2, Classpath Exception, Assembly Exception e os avisos dos módulos ficam em `assets/runtime-data.zip`. Antes de distribuição pública, revisar as obrigações de disponibilização do código-fonte correspondente.
2. O [NDK r30 oficial](https://developer.android.com/ndk/downloads), versão `30.0.16248370`, foi instalado somente em `W:` após verificação do SHA-1 publicado (`9bf167a1985fa7d4a036186b78f702eab9179408`). O launcher original em `app/src/main/cpp/openmc_launcher.c` compila para ELF AArch64. As bibliotecas OpenJDK são extraídas como bibliotecas nativas do APK; `libc++_shared.so` vem do NDK e seu aviso legal fica em `assets/ndk-sysroot-NOTICE.txt`. O [Android impede `execve()` de binários na pasta gravável do app para apps com target API 29+](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission); por isso os executáveis não são instalados em `filesDir`.
3. `tools/prepare_runtime.py` confere o SHA-256 do runtime, a arquitetura das bibliotecas, os caminhos do arquivo e as licenças obrigatórias antes de gerar os assets. `RuntimeInstaller` extrai apenas dados e cria links simbólicos para as bibliotecas do APK. A criação da JVM via `JNI_CreateJavaVM`, os links, o console e o encerramento ainda exigem validação em dispositivo ARM64. O app ainda não possui serviço em primeiro plano para manter o processo vivo quando ficar em segundo plano.

### Falha de inicialização observada no Galaxy S23 FE

O primeiro teste real de `TESTAR JVM ANDROID` terminou com `Failed setting boot class path` e código 1. O OpenJDK deduz o diretório interno do runtime pelo caminho **efetivo** de `libjvm.so`, não por `JAVA_HOME` ou `-Djava.home`. O APK instala `libjvm.so` no diretório nativo do pacote e extrai `lib/modules` em `filesDir/jre25`, portanto o diretório inferido pode não conter `lib/modules`. No Android, o linker resolve o caminho real da biblioteca, inclusive quando ela é aberta por um link simbólico; trocar apenas o argumento de `dlopen` para o link da árvore do runtime não é uma correção confiável.

O launcher agora registra `JAVA_HOME`, os caminhos e tamanhos de `lib/modules`, link e biblioteca nativa, o caminho retornado por `dladdr` e a localização de `lib/modules` inferida desse caminho. `RuntimeInstaller` verifica tamanho e assinatura jimage de `lib/modules`, reinstalando os dados somente se estiverem incompletos. O APK de diagnóstico compila e tem assinatura debug válida; **a JVM continua não validada**. O próximo teste no dispositivo deve registrar as linhas `OpenMC` exibidas no console. Se o diretório inferido não for `filesDir/jre25`, a correção requer um build do OpenJDK que aceite explicitamente o diretório dos módulos ou outro layout nativo suportado pelo Android. Não carregar bibliotecas executáveis de `filesDir` para contornar o layout.

O teste seguinte no S23 FE confirmou o diretório inferido incorreto. A integração prepara `OPENMC_RUNTIME_HOME` para um build Android do OpenJDK adaptado; a proposta de patch, os pré-requisitos de recompilação e os critérios de aceitação estão em [docs/openjdk25-runtime-home.md](docs/openjdk25-runtime-home.md). O `libjvm.so` atualmente empacotado **ainda não contém o patch**. Recompilar apenas o APK não resolve a falha. O WSL não está instalado; sua habilitação exigiria uma mudança importante no Windows e foi interrompida conforme a restrição do usuário. Builds posteriores podem usar `OPENMC_BUILD_DIR` para manter os artefatos gerados em W:.

## Verificações desta etapa

- `assembleDebug` offline: concluído com sucesso. APK debug validado com `apksigner` (assinatura v2).
- Bootstrap Java: teste local com um JAR de teste original retornou `BOOTSTRAP_OK:nogui`. Esse teste usou o JDK do Windows, não a JVM Android.
- OpenJDK 25: SHA-256 do release confirmado; 33 bibliotecas OpenJDK distintas e `libc++_shared.so` do NDK com arquitetura AArch64; dependências dinâmicas restantes são bibliotecas de sistema Android (`libc`, `libdl`, `libm`, `libz`). ZIP de dados e APK passaram em CRC; licença OpenJDK está no ZIP.
- Pendente em dispositivo físico ARM64: instalação dos dados, carregamento da JVM, logs e comandos, parada, memória, segundo plano e execução de um servidor real.

O botão **Testar JVM Android** chama a JVM real pelo launcher nativo e deverá imprimir `JVM_READY version=25.0.5` se a criação da VM funcionar. O procedimento e os critérios de aprovação estão em `docs/android-test-plan.md`; o primeiro teste no Galaxy S23 FE falhou antes desse marcador.

## Planejamento da criação de servidores

A próxima tela deverá permitir escolher Vanilla, Paper, Fabric, Forge ou NeoForge e a versão do Minecraft, validando a compatibilidade entre distribuição, versão e Java. A obtenção de artefatos deverá usar fontes oficiais e respeitar licenças/EULA. A opção de aceitar jogadores sem autenticação oficial deverá ficar **desativada por padrão** (`online-mode=true`), exigir uma escolha explícita do dono do servidor e explicar o risco de falsificação de identidade. Essa tela e essa opção ainda não foram implementadas.
